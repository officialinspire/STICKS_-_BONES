# Installable PWA and offline play

STICKS & BONES installs as a Progressive Web App from its GitHub Pages subpath,
for example `https://<owner>.github.io/STICKS_-_BONES/`. The same build works
under any subpath: the manifest, service worker and every cached URL are relative.

## What's in the build

| File | Purpose |
| --- | --- |
| `manifest.webmanifest` | `id`, `start_url` and `scope` are `./`, so they resolve to the subpath. Display is standalone. Four icons: 192 and 512 px for both "any" and "maskable". |
| `icons/*.png` | Generated by `npm run icons:build` from Cousin's approved portrait atlas (neutral frame, the game's own bust box), on a full-bleed teal field. `apple-touch-icon-180.png` is for iOS. |
| `sw.js` | The service worker, generated by the `sticks-pwa` Vite plugin from `src/pwa/sw.js` with this build's exact file lists. |
| `build.json` | The build id and the shell and asset lists, for diagnostics. |

### Maskable safe area

The maskable safe area is verified, not assumed. A maskable icon may be cropped
to any shape that contains the centred circle of radius 40% of the icon.

- The generator shrinks the art until every foreground pixel (alpha > 8) lies
  inside that circle.
- It records the measured worst radius in `src/assets/icons.json`. Measured:
  0.392–0.395 against a limit of 0.400.
- "Any" icons use the same art, up to 0.46.
- `npm run assets:verify` checks these things:
  - each icon's hash, size and recorded radius;
  - that the icons came from the current portrait sheet;
  - that every manifest icon is a verified generated file;
  - that `start_url` and `scope` are relative.

## Isolation from other INSPIRE apps on the same origin

GitHub Pages serves every repository of an owner from one origin, so other apps
share our CacheStorage, localStorage and service-worker registry.

- **Scope:** the worker is registered at `<app root>/sw.js` with scope = the app's
  directory, computed from the entry chunk's URL. It only answers requests under
  that scope; anything else goes to the network untouched.
- **Caches:** every cache this app creates is named `inspire:sticks-and-bones:*`.
  The worker and the page only ever open or delete caches with that prefix. A
  unit test covers look-alikes such as `inspire:sticks-and-bones-fan:v1` and
  `sticks-and-bones`.
- **No unregistering, no forced takeover:** nothing ever calls `unregister()`.
  The worker never calls `skipWaiting()` on its own.
- **Local data:** saves, settings and statistics use `sticks-and-bones.*` keys.
  "Erase" removes only those keys.
- `npm run pwa` serves a fake second app at `/other-app/` on the same origin,
  with its own worker, two namespaced caches, a generic cache and localStorage
  keys. It asserts that all of these survive first visit, offline play, repair,
  erase and update.

## What is cached, and when (integration stage: four groups)

Every file the worker may store is listed in the build with its **exact byte size** (`sw.js` → `GROUPS`,
also in `dist/build.json`). A download is stored only if its body is complete (a truncated response is
never cached), at most 2 at a time; a quota error stops the job and is reported; nothing throws to the page.
Reading the status never creates a cache.

| Cache | Contents (measured, this build) | When |
| --- | --- | --- |
| `inspire:sticks-and-bones:shell:<build>` | HTML, JS (entry, AI worker and the two lazy Story chunks), CSS, fonts, manifest, the 192-px icons — **11 files, 486 KB** | At install, all or nothing (`cache.addAll`, bypassing the HTTP cache) |
| `inspire:sticks-and-bones:assets:v1` (core) | What Quick Play needs: both patio variants, Cousin's portrait and slam, tile atlas, tabletop, effects, UI/table/pass sounds — **30 files, 1.80 MB** | After the shell, best effort (the name is unchanged so existing installs stay valid) |
| `inspire:sticks-and-bones:story:v1` | Chapter backdrops (full + portrait), the four cast sheets, story accents — **23 files, 3.20 MB** | **Per chapter as it is played** (cache-on-fetch: the current chapter and the prefetched next one), and **in full only when the player chooses "Download the whole story"** |
| `inspire:sticks-and-bones:audio:v1` | Music and the five ambience beds — **7 files, 9.15 MB** | **Optional, only when the player turns on offline audio** (size shown first). Served with byte ranges (206) for `<audio>` |
| — | **Never cached:** PNG source sheets (the build fails if one is bundled), the studio intro video, the 512-px icons | Network only |

**Policy change, deliberate and narrow:** music and ambience used to be "never cached". They are now cached
**only** in `audio:v1`, **only** after the player's explicit choice, with the size disclosed beforehand, and
removable in one tap. Nothing else changed: the first visit caches exactly shell + core
(**2,349,692 B** measured by `npm run pwa`; Stage 12 was 2,188,958 B, when *every* image was precached).

## What is ready offline, and how the game says so (Settings → Offline & storage)

| Line | Meaning |
| --- | --- |
| **✓ Quick Play is ready offline (2.2 MB on this device).** | Shell + core complete: solo, AI partnership, two players, saves, rules, settings |
| **Only the app is ready offline; story scenes download as you play them.** | No story scene is fully saved yet |
| **n of 9 story scenes are ready offline (the ones you have opened, and the next one).** | Counted from the saved files of each scene's backdrop (this screen shape) and cast |
| **The whole story is ready offline (3.2 MB).** | The story group is complete |
| **Music and ambience are an optional 9.1 MB extra download.** / **…saved for offline play (9.1 MB).** | Offline audio off / on |

The case file adds one line for the current scene: **"Saved for offline play."** or **"Needs a connection the
first time (it saves for offline as you play)."** A scene whose art is missing offline still plays with the
drawn backdrop and name tags.

**Downloads (whole story, offline audio):** the button shows the measured size left
(**Download the whole story (3.2 MB)**, **Save music & ambience for offline (9.1 MB)**). Before starting, the
browser's storage estimate is checked; if the files would not fit, nothing is downloaded and the line says
how much is needed and free. Persistent storage is requested (where offered). A progress bar shows bytes.
- **Interrupted** (connection lost, a file cut off, the browser stopped the worker): finished files are kept;
  **Retry (n MB left)** continues.
- **Quota error mid-way:** reported with the sizes; the game keeps working online.
- **Missing optional media** (e.g. an audio file not on the server): skipped and reported
  ("1 audio file was unavailable and skipped"); Retry fetches only what is missing.
- **No storage / no service worker:** the lines say offline files aren't available in this browser.

The player's choices (story / audio) live in a versioned local record, `sticks-and-bones.offline`.

## Updates: "Update available" and how a waiting update is applied

1. A new deploy changes `sw.js` (the build id hashes every emitted file). The new worker installs next to the
   running one and **waits**; checks run on load, on returning to the tab and every 30 minutes.
2. **Update now** is offered on the menu, the case file, the story **scene bar**, and the pause sheet of any
   table (Quick Play or a story hand).
3. **Update now** first writes the stable state and checks the write succeeded:
   - a Quick Play match: the save from the engine state;
   - a story scene or hand: the case progress with the exact line, or the in-progress hand snapshot.

   **If the write is refused**, the player is told ("Your place couldn't be saved") and chooses **Not now —
   keep playing** (nothing reloads) or **Update anyway** (returns to the last saved point). It never claims
   to have saved.
4. Then the table is torn down (no AI move can land), the screen is replaced (no hand visible — checked at
   unload), and the worker takes over.
5. **After the reload, the start tap returns once** to where the player was: the same story line, the same
   hand (engine state identical), the case file, or the saved match. Two-player matches reopen behind the
   privacy cover. The return point is consumed before anything renders, so a second reload goes to the menu.

## Repair and erase (Settings → Offline & storage)

- **Repair offline files** deletes only `inspire:sticks-and-bones:*` caches, then downloads the shell, core
  and **the groups the player chose** (whole story, offline audio) again. **Both save slots (the Quick Play
  save and the Story case progress), settings and statistics are not touched**; other apps' caches and
  workers are not touched.
- **Erase saved game, settings & statistics…** (two taps) removes only `sticks-and-bones.*` keys; offline
  files are kept.

## Evidence (`npm run pwa`)

`npm run pwa` builds the app twice (A and B differ only in `SB_BUILD_TAG`), then
serves both from `/STICKS_-_BONES/` alongside the fake other app. It covers:

1. **Online first visit:**
   - manifest, icons and start URL resolve inside the subpath;
   - worker scope is `/STICKS_-_BONES/`;
   - status reaches ready;
   - only namespaced caches, no PNG or media cached;
   - the byte size is reported.
2. **Offline reload:** the server is down (connections destroyed) and the browser
   is offline. The app starts from cache and **a full hand vs the computer
   completes**. Music is silent, 0 page errors, and 0 app files were requested
   from the network. The only network attempts are the browser's own `sw.js`
   update checks, which fail harmlessly.
3. **Interrupted downloads:**
   - two images are cut off mid-transfer;
   - the status shows "2 of 6 images still to download", and no truncated file
     is cached;
   - **an offline hand completes with vector tile faces**;
   - back online, Repair → ready.
4. **Quota:** DevTools `Storage.overrideQuotaForOrigin` was set to 700 KB (images
   don't fit) and to 40 KB (the shell doesn't fit). Both show the storage message,
   and an online hand still completes.
5. **Update A → B mid-match**, two humans, a hand revealed:
   - Update Available appears in the pause sheet;
   - the screen at unload showed no hand;
   - build B is running afterwards and the saved match is identical;
   - Resume opens covered;
   - the old shell cache is deleted, the new one is present.
6. **Repair and erase:**
   - repair rebuilt our caches and dropped a stale one, with localStorage
     unchanged;
   - erase removed only our keys and kept the offline files;
   - the other app's data was intact after every step;
   - axe found no violations on the offline panel or the pause sheet with the
     update banner.

## Known browser limitations

None of these have been tested on real devices; see `docs/QA.md`.

- **iOS / iPadOS Safari:**
  - No install prompt: players use Share → Add to Home Screen.
  - A home-screen app has **its own storage**, separate from Safari's, so saves
    don't move between them.
  - Script-writable storage, including caches, may be **evicted after about 7
    days without use** for sites that aren't installed. Repair or the next
    online visit restores the files.
  - The 512-px maskable icon isn't used; `apple-touch-icon-180.png` is.
- **Firefox desktop:** service worker and offline play work, but Firefox
  doesn't offer to install sites as apps, so this is a browser tab with offline
  support. Firefox for Android can install.
- **Private browsing:** some modes, such as Firefox private windows, disable
  service workers. The status then says offline isn't available, and the game
  still works online.
- **Storage is "best effort":** the app does not call
  `navigator.storage.persist()`, so a browser under storage pressure may evict
  the offline files. Saves in localStorage follow each browser's own eviction
  rules.
- **Chromium's offline emulation still attempts `sw.js` update checks.** The test
  server sees and drops them. Real offline devices simply fail them.
- **No custom install button:** browsers that support installation show their
  own install UI (for example the install icon in Chrome's address bar).
- **Only Chromium was tested.** Firefox and WebKit weren't available here.
